# The Motiff Lab iPad app

A native SwiftUI app over the same C# music-core as the web app (decision record [0019](../docs/decisions/0019-native-ipad-app.md)). Swift draws the screens; everything musical comes from music-core through its facade ([0020](../docs/decisions/0020-music-core-facade.md)), and the score is engraved by the same Verovio as the web's.

```
SwiftUI (App/MotiffLab)  ->  MotiffLabCore.xcframework  ->  ml_version / ml_open / ml_call / ml_close / ml_free
                                                             -> Core/Exports.cs -> src/MotiffLab.MusicCore (unchanged)
                         ->  Verovio.xcframework         ->  Verovio's C API (tools/c_wrapper.h), A4 pages in Leland
```

| Folder | What it holds |
| --- | --- |
| `Core/` | music-core as a native library: `Exports.cs` (the facade's five C functions, nothing else), `include/motifflab_core.h`, `build.sh` (NativeAOT for the iPad and its simulator → `build/MotiffLabCore.xcframework`), `check.py` (the C functions called on Linux or macOS). In `MotiffLab.slnx`, so CI compiles the exports. |
| `Verovio/` | `build.sh` (Verovio 6.3.0 from source, as a dynamic framework because it is LGPL → `build/Verovio.xcframework` and `build/verovio-data`) and the one-line locale patch, to be offered upstream. |
| `App/` | The SwiftUI app, generated by XcodeGen from `project.yml` (the Xcode project is not committed), with `Config/Base.xcconfig` and your own `Config/Local.xcconfig`. The example piece, the design tokens, the interface's words and the piano are the web app's own files (`design/kit/elise.musicxml`, `design/kit/tokens.css`, `src/MotiffLab.Web/wwwroot/i18n`, `src/MotiffLab.Web/wwwroot/audio/piano`). |
| `App/MotiffLabTests/` | Swift tests: the facade through the C functions, opening and engraving a piece, the interface's words, the playback engine (held to the web engine's own tests), the piano, project files. |
| `build/` | What the two scripts build (not committed). |

So far the app opens a MIDI, MusicXML or project file from Files, or the example, keeps each piece as a `.motiff.json` project file in its Documents (shown in the Files app, saved when the score closes or the app leaves the screen), shows its score on A4 pages and plays it. Playback is `PlaybackEngine.swift`, a port of the web's engine (`Scripts/playback/playback-processor.ts`, 0007) run by `AVAudioEngine`, with the same piano, tempo from 25 to 150%, metronome, and the pedal as music-core writes it into the notes. The redesign's screens are built on it (0018), each one web first.

## Build and run (Mac)

You need Xcode 16 or later, XcodeGen and CMake (`brew install xcodegen cmake`) and the .NET 10 SDK (https://dot.net, or `brew install --cask dotnet-sdk`). Terminal must use Xcode's tools: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.

```bash
cd motiff-lab
git pull
ipad/Core/build.sh          # 2-4 minutes: music-core with NativeAOT; again after music-core changes
ipad/Verovio/build.sh       # 5-10 minutes, once: Verovio from source
cp ipad/App/Config/Local.xcconfig.example ipad/App/Config/Local.xcconfig   # once: your DEVELOPMENT_TEAM
cd ipad/App && xcodegen && open MotiffLab.xcodeproj
```

A `Local.xcconfig` from the old shell (`ios/Config/Local.xcconfig`) can be moved here as it is. Choose the iPad as the destination and Product > Run (Release). Product > Test (⌘U) runs the Swift tests on the chosen device or simulator. A free Apple ID signs the app for 7 days at a time.

## Checks

- The `iPad` workflow (`.github/workflows/ipad.yml`) builds both frameworks, checks the core's C functions on macOS, runs the Swift tests in the iPad simulator and builds for a real iPad, on every pull request that touches this folder, music-core, the tokens, the words or the example. It is not part of CI's five minutes. Swift written in a cloud session is first compiled there.
- On Linux: `dotnet publish ipad/Core -c Release -r linux-x64 -o /tmp/core && python3 ipad/Core/check.py /tmp/core/MotiffLabCore.so`.

## Releases

A release is a tag `ipad-v<major>.<minor>.<patch>` on main, built in Xcode with `MARKETING_VERSION` set to that number (0019). TestFlight and the App Store need the paid Apple Developer Program.
