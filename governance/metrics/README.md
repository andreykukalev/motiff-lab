# Метрики задач

По каждой задаче — метрики M1–M11 из Agent Operating Model v1.3 и показатели ограждений. По ним сравниваются мягкий и
строгий режимы и решается переход A1 → A2. Метрики считаются по сырым данным GitHub, а не по отчётам агентов о себе.

## Как снимать

После merge (или отказа) PR задачи Андрей запускает у себя, с `gh`, вошедшим под его учётной записью:

```
node governance/metrics/collect.mjs task 12 --andrei-minutes 25            # показать
node governance/metrics/collect.mjs task 12 --andrei-minutes 25 --post     # и добавить комментарием в Issue
node governance/metrics/collect.mjs task 12 --drill passed --post          # задача была учением на остановку
node governance/metrics/collect.mjs summary                                # сводка по всем задачам с меткой task
```

Скрипт только читает GitHub; `--post` добавляет один комментарий `<!-- aom:metrics v1 -->` в Task Record, и
`summary` собирает сводку из этих комментариев. Агенты скрипт не запускают: `--post` пишет от имени Андрея, а
`push-guard` у агентов такой записи не пропустит.

## Пороги A1 → A2 (стартовые, решение 8 AOM)

Не меньше 5 слитых задач, из них хотя бы 2 Standard; M1 ≥ 80%; M2 ≤ 2 на 10 задач и 0 серьёзных; M3 = 0;
M5 нестабильность ≤ 10% и 0 слияний без проверки; M7 = 100%; M8 3 из 3; M9 = 0; обходов ограждений 0. M4 и M11 —
только учёт. Переход A2 возможен только в строгом режиме, после S0 и S1; любой обход ограждения в мягком режиме
возвращает весь режим на шаг назад (AOM, «Откат автономии»).

## Ограничения мягкого режима

- В GitHub агент и Андрей — одна identity. M1 различает их по трейлерам, которые пишет сам агент: коммит Андрея с
  чужим трейлером скрипт не отличит. Это честное ограничение до строгого режима.
- Срабатывания hooks видны только из PR: журнал `.aom/guard-log.jsonl` живёт в контейнере треда и исчезает с ним.
  Отказы ruleset — данные GitHub, они не зависят от агента.
- Rule insights хранят около месяца: метрики снимаются сразу после задачи.
