# Архитектурный совет

Роли, правила и запреты — в `governance/roles/council.md`; прочитай его и `governance/roles/common.md` до первого
шага. Ты — модератор: ведёшь раунды, проверяешь факты, пишешь записи, не голосуешь.

## Когда

- Андрей просит совет («созови совет по …», `/council <тема>`) или координатор передал такую просьбу с его
  сообщением. Без вопроса Андрея совет не начинается.
- Полный совет — решение, которое дорого отменить (архитектура, контракт, формат, монетизация). Лёгкий — всё
  остальное: исследователь, два места по вопросу, слепое место, R1 и R2.

## Запуск мест

Каждое место — субагент с определением из `.claude/agents/`:

| Место | `subagent_type` | Модель |
| --- | --- | --- |
| Исследователь | `researcher` | sonnet |
| Ядро и данные | `council-seat-core` | opus |
| Веб | `council-seat-web` | sonnet |
| iPad | `council-seat-ipad` | opus |
| Стоимость и поставка | `council-seat-cost` | sonnet |
| Адвокат варианта N | `council-advocate` | sonnet; haiku, если вариантов больше трёх (передай `model: haiku` при запуске) |
| Слепое место | `council-blind` | opus |

**Если такого `subagent_type` нет** (облачные треды claude.ai на 2026-11-08 не читают `.claude/agents` репозитория):
запусти `Explore` с `model` из таблицы, а промптом передай сначала строку

> Используй только Read, Grep и Glob. Никаких Bash, MCP-инструментов (GitHub и других) и записи куда-либо.

затем текст определения целиком (всё после второй строки `---`) и задание раунда. Исследователю вместо этой строки —
«Bash только для чтения: git log, git show, git diff, git grep, wc, ls, grep, find; никаких MCP-инструментов и записи».

**Честно о пределах.** У `Explore` есть `Bash` и все MCP-инструменты, включая запись в GitHub, а deny из
`.claude/settings.json` в облачном треде не действует. Поэтому в облаке «только чтение» держится строкой в промпте и
определением места, а не техникой. Список инструментов из frontmatter действует только там, где агенты загружаются
по имени (Claude Code на компьютере). Если отчёт места показывает, что оно запускало что-то кроме чтения, модератор
останавливает совет и пишет Андрею.

Задание раунда в промпте каждого места: путь папки совета, какие файлы читать, имя файла инструкции раунда, для
адвоката — номер и название варианта. Места одного раунда запускаются параллельно, в одном сообщении.

## Где идёт совет

| | Облачный тред claude.ai | Claude Code на компьютере Андрея |
| --- | --- | --- |
| Места | Запасной путь через `Explore` (выше) | По имени, со списком инструментов из определения |
| Папка совета | `/mnt/project-files/councils/<тема>/` (сетевая: путь с косой чертой на конце, перечитать файл через ~10 секунд после записи) | Папка вне репозитория рядом с клоном: `../motiff-lab-councils/<тема>/`; после совета Андрей при желании переносит её в файлы проекта |
| Запись решения | Claude Doc | `record.md` в папке совета |
| Вопросы Андрею | Карточки решений (`request_decision`) | Вопрос с вариантами (`AskUserQuestion`), рекомендация первой |
| Проверки рантайма | Нет .NET SDK: «проверить до стройки» | Есть SDK — можно проверить сборкой |

Дальше в шагах — названия облачного треда; на компьютере подставь правый столбец.

## Папка совета

| Файл | Кто пишет | Что |
| --- | --- | --- |
| `README.md` | модератор | Ход совета по времени, ссылка на запись решения, ответы Андрея |
| `brief.md` | модератор с Андреем | Замороженный бриф (шаблон `templates/brief.md`) |
| `concept-*.md` | Андрей | Продуктовая концепция, если он её дал, целиком |
| `lenses.md` | модератор | Линзы мест, если для этого совета они отличаются от определений |
| `facts-baseline.md` | исследователь | Факты `F<n>` на названном SHA |
| `r<N>-instructions.md` | модератор | Инструкция раунда (шаблоны `templates/r1.md`, `r2.md`, `r3.md`) |
| `r<N>/<место>.md` | модератор | Отчёт места без правок |
| `facts.md` | модератор | Проверенные факты `V<n>` (шаблон `templates/facts.md`) |
| `usage.md` | модератор | Расход: место, модель, токены, время, вызовы по каждому запуску |

## Шаги

1. **Бриф.** Заполни `templates/brief.md` из вопроса Андрея. Нейтрально: без того, к чему он склоняется в
   архитектуре. Его продуктовая концепция — целиком, отдельным файлом. Отправь бриф Андрею и спроси одной карточкой:
   подтвердить, поправить, полный или лёгкий совет.
2. **Факты, параллельно с подтверждением брифа.** Запусти исследователя с вопросами брифа и SHA текущего `main`.
   Сохрани `facts-baseline.md`, перепроверь три–пять чисел сам.
3. **Заморозка.** После «да» Андрея бриф больше не меняется (`governance/roles/council.md`, «Модератор»).
4. **R1, независимо.** Все места параллельно. Слепое место читает только `brief.md` и `facts-baseline.md`.
5. **Проверка фактов.** Каждое утверждение, на котором позиции расходятся или от которого зависят, — по коду, с
   `файл:строка` на SHA. Запиши `facts.md`. Выпиши сходство и живые разногласия (a), (b), … в `r2-instructions.md`.
6. **R2, перекрёстная атака.** Все места видят все отчёты R1 и `facts.md`.
7. **Проверка фактов** для каждого нового утверждения, на котором держится атака. Допиши `facts.md`.
8. **R3, финал** (только полный совет). Устоявшиеся пункты S1… и открытые узлы C1… с числами — в
   `r3-instructions.md`.
9. **Проверки, которые просили места**, если они дешёвые и безопасные; что требует сборки или рантайма (в контейнере
   нет .NET SDK), — списком «проверить до стройки».
10. **Запись решения** — Claude Doc на русском по `templates/record.md`.
11. **Ворота.** Вопросы Андрею карточками решений (`request_decision`), по одному на карточку, рекомендация первой.
    Лимиты карточки в байтах, кириллица — 2 байта на букву: название варианта ≤ 40 байт (около 20 букв), следствие и
    причина ≤ 200 байт (около 100 букв). Ответы — в `README.md` в тот же ход; после последнего ответа сказать, что
    ворота закрыты.

## Частые ошибки

- **Бриф меняется после R1** (в пилоте — четыре раза до R1). Меняется вопрос — новый совет.
- **Факт, который одно место сказало уверенно, становится посылкой.** До следующего раунда — только через `facts.md`.
- **Расплывчатая атака.** «Может быть сложно» — не удар: вернуть месту за сценарием.
- **Технический вопрос в воротах.** Если места согласны и проверка подтверждает — это не вопрос Андрею, а пункт
  записи «решено проверкой».
- **Запись решения только в чате.** Всё — в папке совета и в Claude Doc.

## Готово, когда

- [ ] Бриф подтверждён Андреем и не менялся после R1
- [ ] Все места запускались только на чтение, их отчёты сохранены без правок
- [ ] `facts.md` закрывает каждое спорное утверждение: проверено (как) или не проверено (почему важно)
- [ ] `usage.md` заполнен
- [ ] Запись решения опубликована, ворота заданы, ответы Андрея в `README.md`
