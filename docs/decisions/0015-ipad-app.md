# 0015 · The iPad app: a native shell around the web app, and pencil marks on the score

Status: proposed, 2026-10-30. Andrei asked to start the iPad app, built in Xcode on his Mac, with the Apple Pencil writing on the score as in the sheet-music app he uses now.

> 2026-11-01: superseded in part by the redesign ([0018](0018-redesign.md), section 14) and by 0019, still to be written: the iPad app is fully native Swift, and pencil marks move from a device store into the project file. The Swift shell described here remains until the native app replaces it.

## Context

The web app (0001, 0012) already runs on the iPad in Safari, and the workspace was laid out for it (PR #120's mockups, `docs/ui-conventions.md`): the score, the roll, Focus mode at the piano, touch-sized controls. PR #120 proposed a .NET MAUI Blazor Hybrid app; it is still open, with its decisions on publishing undecided. Since then the scan server and the API moved to Azure (0014), so nothing the app needs runs on the player's computer any more.

Andrei builds and installs with Xcode on his Mac, with a free Apple ID for now (an app signed that way runs for 7 days, then is installed again from Xcode) and the paid programme later. No Xcode Cloud or TestFlight is assumed.

The options weighed:

- **SwiftUI rewrite.** Native through and through, but every screen and the engine's bridge would be written a second time, and music-core (C#) would need a port or a bridge. Out of proportion for Stage 1.
- **MAUI Blazor Hybrid (PR #120).** Reuses the Razor components and runs music-core natively, but needs the Razor components moved into a class library, the MAUI workload on the Mac, and a second host to keep building. Worth it once the app needs native audio (Stage 2), not to get started.
- **Capacitor.** A JavaScript toolchain and plugins the project does not otherwise use.
- **A small Swift shell around the deployed web app (chosen).** One `WKWebView` that opens the deployed web app, plus the few things a browser tab cannot do. Every change to the web app reaches the iPad on its next start, without building the app again.

## Decision

1. **`ios/` is a Swift app (iPadOS 17 and later, iPad only for now) that shows the deployed web app** (`swa-motifflab`) in a `WKWebView`. The Xcode project is generated by XcodeGen from `ios/project.yml` and never committed; signing and the address are build settings (`ios/Config/Base.xcconfig`, overridden per Mac in `Local.xcconfig`). CI does not build it.
2. **The shell adds only what the web app cannot do in Safari:**
   - sound with the silent switch on (the audio session's playback category);
   - a screen that stays on while the app is open, for the piano;
   - the Apple Pencil's double tap and squeeze, relayed to the page as a `motiff-pencil` event (`PencilBridge.swift`), following the player's choice in Settings > Apple Pencil;
   - exported files (project files, MIDI) offered to Files, and other sites opened in Safari rather than in place of the workspace;
   - offline start: the web app is the app's one app-bound domain (`WKAppBoundDomains`), which is when WebKit runs its service worker, so after one start with a connection the app opens without one, as the PWA does;
   - `window.motiffNative` and `MotiffLabApp/<version>` in the user agent, so the page can tell it runs in the app.
3. **The web app stays the one implementation.** Origins, IndexedDB, the scan server's and the API's CORS rules are the web app's own, so nothing in Azure changes. Projects saved in Safari and in the app are kept apart by iPadOS (each has its own storage); export and import, or saving online (0014), move them.
4. **Pencil marks on the score.** The player writes on the score by hand, as on paper:
   - The Pencil (any pen: `pointerType` `pen`) writes at any time; a finger never writes, so the hand resting on the glass and a finger scrolling leave no marks; a tap with the Pencil picks a note or a bar as a click does. With the **Pencil** tools turned on, the mouse writes too. The tools are a pen in black, red or blue (with the Pencil's pressure), a highlighter, an eraser that takes whole strokes, Undo, and Clear marks (which Undo brings back). A double tap switches to the eraser and back.
   - The score reflows with the window, so a mark is kept against **the bar it starts in** (its start tick), where in the bar it starts (a share of the bar's width) and its height from the bar's top staff line, with its shape in staff spaces (`Scripts/score/pencil-marks.ts`). After a new layout each mark returns to its bar at the staves' size. The as-written and generated scores share their bars, so marks show on both; the score with a variation in it shows none.
   - Marks belong to the piece and stay on the device, in their own IndexedDB database (`Scripts/storage/pencil-store.ts`), saved half a second after each change and deleted with their project. They are not yet in the project file, so export and saving online do not carry them; adding them is a project file version change for later.
   - Marks are the player's own writing and are never read as music: nothing turns them into notes, facts or analysis.
   - This works in Safari on the iPad as well as in the app, so the web app stays the place it is tested (`tests/e2e/pencil.spec.mjs`, Chromium, where the DevTools protocol can drive a pen).

## Consequences

- The app needs a connection for its first start, and loads the web app's latest version whenever it has one. A broken deploy reaches the iPad as it reaches the browser.
- App Store review can refuse an app that is only a website (guideline 4.2). Before submitting, the shell should carry the web app inside it (served from the bundle under a custom scheme) and add native value beyond the Pencil and audio; MAUI Blazor Hybrid (PR #120) remains the route when native audio is needed (Stage 2).
- Sign-in (0014) in the app is not wired yet: Microsoft's sign-in pages would open in Safari. When the tenant exists, its sign-in host is added to the app-bound domains and allowed in the web view, or the app signs in natively with `ASWebAuthenticationSession`.
- A free Apple ID signs the app for 7 days at a time and for up to three devices; the paid programme removes that and opens TestFlight.
